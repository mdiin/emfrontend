## a. The actual cause (and why the recorded explanation was wrong)

**The symptom.** An element rendered as an empty grey box: white card, grey
border, no name, no field lines.

**The mechanism.** A *placement whose element record this client was never
given*. `draw-element-card` is called with `(get elements element-id)`
(`src/em_frontend/canvas.cljd:395-405` before the fix), so with no record it
drew the nil-element fallback: `(:kind nil)` → the grey fallback
(`canvas.cljd:306` after the fix, 286 before), `(or (:name nil) "")` → "", and
`model/canvas-fields` on nil → `[]` (kind `nil` is not in `canvas-field-kinds`).
That is exactly the reported card, including the absence of the red
incomplete ring (`(false? nil)` is false).

Why could a placement name an element the client had never been given?

1. The snapshot carried elements **only where the projection reaches them** —
   nested under a placement, or as a `{id,name}` end of a connection
   (`../thecli/src/emcli/app.clj:116-168`, the docs' populated example
   `../thecli/docs/change-stream.md:57-118`). There was no top-level element
   list.
2. An element that was in the model but *unplaced and unwired* was therefore in
   no snapshot at all. That is a normal, valid model state:
   `create-element` places nothing (`../thecli/src/emcli/rules.clj:213-231`),
   `place-element` is a separate operation, and none of the six invariant
   families in `../thecli/src/emcli/invariants.clj` requires an element to be
   placed.
3. `place-element` emitted **only** the placement
   (`../thecli/src/emcli/rules.clj:344`:
   `(commit store :PlaceElement [(created :placement p)] p)`), naming the
   element by bare id. And the `CreateElement` delta that would have carried it
   had been emitted before this client subscribed, so it was never delivered
   (SSE has no replay — `../thecli/docs/change-stream.md:334-338`).

So: connect (or have connected) → the element is unplaced, so it is in no
snapshot → place it → a placement delta referencing an element the store has no
record for → the nil-element fallback → the grey box. Reloading
(`ReloadModel`, `em-frontend.allium:1149`) takes a fresh snapshot, and by then
the element *is* placed, so the next seed nests its full record and the card
fills in — which is why the Cmd-R button looked like the cure.

**Why cause 2 is not the cause.** The recorded note named
`element-updated`'s `assoc-in` (`store.cljd` line 163 then) as the natural
root-cause fix. It cannot be: element deltas always carry the **full** entity —
`../thecli/src/emcli/rules.clj:20-26` (`updated` fetches the whole entity and
injects the derived flag) and `../thecli/docs/change-stream.md:184-195` ("Update
(full new entity state is sent)"). A full delta over a full record cannot erase
`:kind`/`:name`/`:fields`. Replace-vs-merge is a **latent** robustness gap, not
this bug — the frontend never received *any* element entity for the offending
id.

**What the other recorded causes actually contribute.**
- Cause 1 (unknown `:kind` → grey) is the *colourer*: it is why the ghost was
  grey rather than visibly absent.
- Cause 3 (a partial element can reach the store) explains the milder second
  flavour: a snapshot connection endpoint registers `{id,name}`, so such an
  element placed later would have rendered as a grey card **with a name** and no
  fields. It could never explain "no name".
- Cause 2 stays open by design (see section h).

## b. The frontend guard (`emfrontend`)

An element record the client does not hold must never be drawn as an element.

- `store.cljd/element-loaded?` — the one definition: a loaded record is a full
  Element, i.e. it carries `:kind` (every element entity on the wire does; a
  `{id,name}` endpoint reference deliberately does not). Nil and partials are
  not loaded.
- `canvas.cljd/card-presentation` — a new pure seam (`[element-id element]` →
  `{:unloaded? :name :outline-color :incomplete?}`), so the decision is testable
  without a widget, the way `connection-presentation` is. Loaded: the element's
  name, its kind's outline colour with the grey fallback, the red-ring flag.
  Unloaded: `:unloaded? true`, the reference's name when it carries one else
  `"element #<id>"`, and **amber** rather than grey — grey is exactly what a
  *known* element with an unknown kind gets, so it cannot mark "no record".
- `draw-element-card` consumes it: an unloaded card is not filled, lists no
  fields and no wireframe, claims no completeness ring, and draws a
  `"not loaded"` line under the label. The cell and the default card size are
  unchanged, so nothing reflows (`layout.cljd:25-32` sends an unloaded element
  to the unnamed band because `(:swimlane nil)` is nil).

**The same lie one surface over, found by the weed pass and fixed too.**
Clicking the placeholder opened `surface ElementDetails`, whose
"information complete" line was green for a record the client did not hold
(`(not (false? nil))` is true). Now `app.cljd/element-details-presentation`
answers three ways — `:not-loaded`, `:incomplete`, `:complete` — and the panel
shows no kind, context, swimlane, image or fields for `:not-loaded`, labelling
the element by the name its reference carries else by its id
(`panels/element_details.cljd`).

## c. The wire fix (`../thecli`) — the root cause

The snapshot is now a complete entity seed for the state it captures:

- `app.clj/snapshot` carries `model.elements`: **every** element of the model,
  each in the canonical record shape the deltas use, built by the new
  `model.clj/canonical-entity` — which `rules/updated` and
  `rules/create-element` were refactored onto, so the snapshot and the delta
  paths cannot disagree about an element's shape. That refactor also removed
  the duplicated `is_information_complete` injection.
- `docs/change-stream.md` and `docs/change-stream.schema.json`: `elements` added
  and **required** (`items: $ref #/$defs/Element`); the snapshot section, the
  worked example and the "Consuming the stream" section rewritten around it
  (element identity now comes from `model.elements`, not from the placement and
  connection refs).
- `event-model.allium`: the `@guidance` paragraph that *was* the bug in prose
  ("An entity that is never placed or wired appears in no snapshot (the
  projection is placement-bound) even though the delta that created it still
  arrives here") was rewritten; `ChangeStream.CanonicalShape` and the `snapshot`
  signature comment state the seed's completeness; `surface ModelChangeStream`'s
  `exposes` list now declares the registry; and the comment on the placement's
  field projection no longer claims subfields travel only in the export.
- `test/emcli/change_stream_check.clj` gained, beyond the schema checks:
  - `snapshot-reference-violations` — every element id the snapshot mentions
    must be in its own registry;
  - `snapshot-registry-violations` — the registry must contain the model's whole
    element list (compared against `m/elements`, not against the expression the
    snapshot iterates), every placement's nested projection must agree with its
    registry entry on the facts both carry (values only; key presence is what
    the wire genuinely differs on) and its fields must be a shape-only
    projection of the registry's recursive ones, an entry's `:swimlane` must
    resolve, and the scenario's nested field must actually reach the validated
    payload (or the recursive Field shape is unvalidated while the docs claim it
    travels);
  - `seed-then-place-violations` — the regression itself, driven through the
    real paths: an element created before a subscriber connects, then placed
    while it listens, must be resolvable from that subscriber's seed.
  Each was verified to bite by mutation (emptying the registry → 4 violations;
  falsifying the nested verdict → 1), and one bug in the new check itself was
  caught and fixed while doing so (`element-facts` looked up a literal `:k`).

## d. How the frontend consumes the seed

- `stream.cljd/normalize-snapshot` seeds `:elements` from `model.elements`, so a
  placement or connection is a pure reference into it. The projection walks were
  reduced to **per-id gap-fillers** that only run when no record arrived (a
  snapshot predating the registry), with the registry seeded first so a reduced
  projection can never replace a canonical record.
- `norm-element-ref` (new): a spec step's element ref is reduced to the bare id
  on both paths. The snapshot nests `{id,name}` there and a delta carries the
  bare id, so the store used to hold two shapes for one field and the
  specification panel rendered "When: " with a blank element name for every
  snapshot-seeded model (`panels/specification_expanded.cljd:9-15` feeding an
  id lookup). Detection uses `dart/is?` against `dart:core/Map`, because
  `map?` is false for a decoded JSON object — the same reason
  `norm-wireframe-node` tests its attrs slot that way.
- The `real-snapshot` fixture was **regenerated from the real code path** (a
  scripted `emcli.commands/run` session, recipe and ids recorded above it),
  rather than hand-edited, because its whole value is being a wire capture. It
  now includes the unplaced element (id 10) the bug is about and a specification
  step with a nested `{id,name}` ref (11/12).

## h. Decisions, rejected alternatives and what is still open

Deliberate, with the alternative rejected:

- **Require the registry, keep a gap-filler.** A snapshot with no `elements` is
  malformed under the new schema, but the projection walks stay as per-id
  gap-fillers so a new frontend still works against an emcli predating the
  registry (and so a partial record renders as an honest placeholder rather than
  a card with no fields). Rejected: deleting the fallback outright (breaks
  version skew for no gain) and keeping two competing sources of truth (the
  bug's shape). The gap-filler path is pinned by
  `normalize-registry-less-snapshot-fills-elements-from-its-projections-test`.
- **Amber, not grey, for the placeholder outline.** Grey is already the
  unknown-kind fallback for a *loaded* record, so it cannot also mean "no
  record". Colours are renderer constants the spec does not pin; the tests pin
  that the two are told apart.
- **Records the frontend is never given are tolerated, not rejected.** The
  store keeps the reference as the wire sent it, the predicate documents what a
  current stream satisfies, and the surfaces state what is drawn. Rejected:
  making the store invent or drop the reference, and weakening the predicate
  until it is vacuous.
- **The placeholder is now defence-in-depth.** With the registry in the wire, a
  *current* emcli stream cannot produce an unresolved placement: an element
  either existed at snapshot time (so it is seeded) or was created afterwards
  (so its `CreateElement` delta arrives before any reference to it, deltas being
  delivered in commit order). The guard therefore covers version skew and any
  future re-divergence, which is why it is kept and tested rather than treated
  as dead code. The same reasoning made the per-entity "which fields are element
  references" check unnecessary; that suggestion was declined and recorded.
- **Not fixed, by design:** grey-box causes 2 and 3 (see below); the
  unknown-kind grey fallback, now unreachable from a current wire and kept as a
  defensive default; `GET /model`'s own element projection in `../thecli`.
- **Not covered by tests** (unchanged from the connection-status session, G1):
  the painter's *drawing* of the placeholder (fill, "not loaded" line, the
  branch that chooses a wireframe or the canvas fields) and the app-bar mount.
  `card-presentation` — the pure seam — is the pinned decision;
  `canvas_test.cljd` also pins that an unresolved placement keeps its cell. This
  repository has no widget harness; `cljd.test` supports one
  (`:runner (ft/testWidgets [tester])`), so the gap is this repo's, not the
  framework's.
